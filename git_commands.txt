These are the Git commands I ran for this assignment, in the order I
needed them, with a short note on what each one did for me.


--- Getting the repository started ---

git init -b main
    Turned my project folder into a Git repo. The -b main part makes the
    first branch "main" instead of the older default "master".

git config user.name "Kushal Talati"
git config user.email "<my GitHub email>"
    Told Git who I am for this repo only, so my commits carry my name.

git status        (also: git status --short, git status -sb)
    My "where am I" command. I ran it to see what was untracked, changed
    or staged. --short is the compact view and -sb adds the branch line,
    which I used at the end to confirm main matched origin/main.


--- Saving work ---

git add <file>
    Picks which changes go into the next commit (staging). I added files
    by name every time rather than using "git add .".

git commit -m "<message>"
    Takes whatever is staged and stores it as a commit with my message.

git diff
    Before committing an edit I ran this to see exactly which lines I
    had changed (+ for new lines, - for removed ones).


--- Working on a branch ---

git branch feature
    Made the feature branch from the commit I was on. It does not move
    me onto it.

git branch
    Lists my branches; the star marks the one I am on.

git switch feature   /   git switch main
    Moves me between branches. Same job as the older git checkout.

git merge --no-ff feature -m "<message>"
    Run from main to bring in the feature branch work. I added --no-ff
    because otherwise Git would just fast-forward and the history would
    look like one straight line with no sign of the branch.


--- Looking at history ---

git log --oneline --graph --all --decorate
    The view I used to show the history: one line per commit, with the
    branch and merge drawn on the left and branch names in brackets.

git log --oneline -3
    Only the latest three commits. Handy for the before/after of the undo.

git log --pretty=format:'%h | %an | %ad | %s'
    Same history but printed with the columns I picked (hash, author,
    date, message).

git show --stat --format='%h %s' HEAD
    Details of one commit. I used it on the revert commit to confirm
    that it removed the line I had added.


--- .gitignore ---

git check-ignore -v <path>
    Answers "is this file ignored, and by which rule?". This is how I
    proved that debug.log and temp/ were caught by my .gitignore.


--- Undoing a commit ---

git revert HEAD --no-edit
    My undo. It does not delete the bad commit; it adds a new commit
    that cancels it out, so nothing is lost and the history on GitHub
    still shows both. --no-edit keeps the automatic "Revert ..." message.


--- GitHub ---

git remote add origin <repo url>
    Links my local repo to the GitHub repo and calls that link "origin".

git remote -v
    Prints the remote URLs so I could check the link was right.

git push -u origin main
    First upload of main. The -u remembers origin/main as the default
    target, so afterwards plain "git push" is enough.

git push origin feature
    Uploads the feature branch too, so it can be seen on GitHub.

git push
    Sends any new commits on my current branch to GitHub.


Not a Git command, but used once:
gh repo create kushaltalati/git-workflow-assignment --public
    GitHub's command line tool. It created the empty public repo for me,
    the same as clicking "New repository" on the website.
